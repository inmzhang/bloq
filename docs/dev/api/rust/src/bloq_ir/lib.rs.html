1//! Program IR for bloq compiler output.
2//!
3//! [`Bloq`] is the public, circuit-bearing graph IR produced by `bloq_compile`
4//! and consumed by backend emitters.
5//!
6//! ## Traversal
7//!
8//! Reads are id-native: every graph level (the [`Bloq`] top level or a region
9//! [`SubGraph`] body) exposes the same accessors — [`SubGraph::node`],
10//! [`SubGraph::nodes`], [`SubGraph::incoming`]/[`SubGraph::outgoing`] (yielding
11//! [`BloqEdgeRef`]s), the dataflow queries [`SubGraph::value_inputs`] /
12//! [`SubGraph::value_output`] / [`SubGraph::boundary_outputs`] — and [`Bloq::walk`]/[`Bloq::levels`]
13//! recurse through region bodies with a [`LevelPath`] for cross-level node
14//! identity. The underlying petgraph storage is not public API.
15//!
16//! ## Derived reads
17//!
18//! Three layers sit on top of raw traversal, for questions a consumer would
19//! otherwise answer by matching on node variants itself:
20//!
21//! - **Structural queries** ([`Bloq::regions_of`], [`Bloq::selection_seams`],
22//!   [`Bloq::node_by_block`], [`SubGraph::quantum_tail`], …) name a program's
23//!   recurring landmarks. Callers use them to construct [`MemoryRoundTarget`]s
24//!   for [`Bloq::insert_memory_rounds`] or [`Bloq::insert_memory_rounds_batch`].
25//! - **[`Bloq::resolve_classical`]** folds the classical dataflow graph under
26//!   a fixed path into the measurement recipe behind a node's value, and
27//!   **[`Bloq::classical_value`]** answers the other half of the same
28//!   question: the bit that path already fixes, including an activation predicate.
29//! - **[`NodeKey`]** is a provenance-derived node identity that survives
30//!   recompilation, for lining one program up against another compile of the
31//!   same block graph.
32//!
33//! ## Exhaustive data enums (deliberate)
34//!
35//! The data enums ([`BloqNodeKind`], [`ClassicalNode`], [`RegionNode`],
36//! [`NodeProvenance`], [`ValueRole`], …) are intentionally **not**
37//! `#[non_exhaustive]`: a backend must fail to compile — not silently
38//! wildcard — when the IR grows a construct, because an unhandled node kind
39//! would emit wrong output rather than error (e.g. `bloq_stim` rejects each region
40//! variant by name). Do not "fix" this by adding `#[non_exhaustive]` to them;
41//! error enums, by contrast, are non-exhaustive.

135/// Circuit vocabulary embedded by Bloq IR templates and annotations.
136///
137/// Execution backends depend on `bloq_ir` alone and use this module instead of
138/// reaching through the IR to its `bloq_circuit` implementation dependency. The
139/// glob is deliberate: the whole vocabulary travels together, and enumerating it
140/// here would only add a second list to keep in step with `bloq_circuit`.
141///
142/// The few circuit types that appear in `bloq_ir`'s own signatures
143/// ([`Basis`], [`CoordinateOverflowError`], [`FlattenLimits`]) are *also* at the
144/// crate root, so those have two paths on purpose — the root one so a signature
145/// is nameable without this module, this one so a backend can take the lot.
146pub mod circuit {
147    pub use bloq_circuit::*;
148}
